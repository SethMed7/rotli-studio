# quokka-film — Rotli's code-drawn story film

A 60 s, 1920×1080, 30 fps film about what Rotli is. The Rotli quokka is the lead, and
Rottnest supplies the hints. Every frame is drawn by one pure JavaScript function, and the
score is synthesized sample by sample. Nothing is filmed, sampled, or generated by an image
model. This folder sits under the gitignored `/marketing/` and is its own npm project
(Node 20+), separate from the Rotli app.

Built on the [anidoodle](https://github.com/alexgreensh/anidoodle) engine (Apache-2.0). It was
scaffolded with `scaffold.mjs --film rotliStory`, and the engine files under `src/canvas-core/*.ts`
and `tools/` are the engine's own. Story and cue table: [`story.md`](story.md). Score as text:
[`score.txt`](score.txt).

## Outputs (`out/`)

| file | what |
|---|---|
| `rotli-story.mp4` | the film, H.264 + AAC score |
| `rotli-story.html` | the same film as one offline HTML file (click / space to play, arrows to step) |
| `rotli-story-poster.jpg` | end-card poster frame |
| `contact-sheet.png` | 20 frames across the film |
| `poselab*.png` | the character rig proof: every pose, filled + blinking |

## Commands

```sh
npm install && npx playwright-core install chromium   # once (plus python3 + Pillow, and
                                                      # `brew install potrace` for the importer)
node tools/render.mjs rotliStory --out out/rotli-story.mp4   # ~15 s, prints a determinism probe
node tools/gate.mjs rotliStory --mp4 out/rotli-story.mp4     # determinism, contract, dead air
node tools/frames.mjs rotliStory 300,720,1790 --sheet out/x.png   # review chosen frames fast
node tools/still-frames.mjs out/rotli-story.mp4                    # identical-consecutive-frame finder
node tools/score.mjs > score.txt                                   # the score, bar by bar
python3 tools/import-quokka.py    # re-import the quokka from ~/rotli/src/assets/characters
```

## How the character works

`tools/import-quokka.py` copies the canonical line art from `src/assets/characters/*.svg` in
as path data. The walking, thoughtful, listening and attention concept poses exist only as raster
sources, so they are ink-thresholded and traced with potrace. `quokka/rig.ts` fills the Cocoa body
from that outline: a flood fill that closes hairline gaps first, so the fill can never drift off
the line. It finds each pose's eyes as solid round ink blobs, which gives every pose a blink. It
draws around the feet with squash, lean and breathing. `rotli/actor.ts` adds the living habits:
blinks on the global frame, a breathing cycle, hop arcs with a takeoff stretch and a landing
squash, and pose swaps that pop.

## Where it deviates from anidoodle

- **Brand fonts are embedded** (General Sans, Baloo 2 for the wordmark), so the gate's two
  "no embedded binary asset" checks fail by design. Everything else passes.
- The quokka is Rotli's own art imported as geometry, not a from-scratch drawing.
- The score is pushed toward energetic from the turn (kick + shaker), which goes beyond the
  plain music-box recipe.

## What is verified, and what is not

- Verified by measurement: determinism (12/12 frames across page counts and orders, audio
  identical across sessions), the contract scan, no dead air (no identical consecutive frames,
  no 15-frame window under 0.5% change), −19 LUFS integrated with a −4 dBFS peak, no silence,
  a spectral centroid of about 2.4 kHz (bright plucks, no pads).
- Reviewed by eye: contact sheets of every shot. A second pass came from Antigravity, which
  watched frames but could not hear the audio.
- **Not verified: how it sounds and how the motion feels at speed.** Only a person can judge
  those.
